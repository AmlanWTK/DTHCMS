# Contributing to DTHCMS

## The one rule that matters most

**Never commit real patient data.** Not in fixtures, not in test files, not in screenshots,
not in issue descriptions, not "temporarily". Synthetic data is generated by CP13 and is the
only acceptable test data. This rule has no exceptions and no emergency override.

## Working agreement

1. Work happens one checkpoint at a time, in the order given by `docs/implementation-plan.md`.
2. A checkpoint is not started until the previous one is explicitly approved by Dr. Nahid.
3. Nothing in a checkpoint's **OUT OF SCOPE** list is implemented, however tempting.
4. A new ambiguity discovered mid-implementation is **stopped on and raised** as an open
   decision (`docs/implementation-plan.md` §3), never resolved by guessing.
5. Clinical rules, thresholds, templates and warning text are authored by Dr. Nahid.
   Engineering builds the machinery; the clinician supplies the medicine.

## Branches and commits

- `main` is protected. Work happens on `cpNN-short-description` branches
  (e.g. `cp02-architecture-guardrails`).
- Commit messages follow [Conventional Commits](https://www.conventionalcommits.org/):

  ```
  feat(patient): add duplicate detection on national ID
  fix(sync): stop retry loop dropping the last queued event
  docs(adr): record the modular monolith decision
  chore(ci): pin golangci-lint version
  ```

  Allowed types: `feat` `fix` `docs` `style` `refactor` `perf` `test` `build` `ci` `chore` `revert`.
  A `cpNN:` prefix in the scope is encouraged for traceability: `feat(cp06/db): add ledger schema`.

- The commit-message hook enforces this locally; CI enforces it on pull requests.

## Before you open a pull request

```powershell
.\scripts\verify.ps1     # or: make verify
```

Then complete the checklist in the pull request template. It is the project
Definition of Done in short form — an unchecked box is a request for review, not a formality.

## Code review

Every pull request needs one approval. Clinical logic (calculations, safety rules, gates,
prescription content) additionally needs Dr. Nahid's confirmation that the **behaviour** is
clinically correct — a passing test only proves the code does what the developer intended.
