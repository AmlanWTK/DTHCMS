## 34. STALE-EGFR-IS-NOT-CURRENT-RENAL-FUNCTION

**Metformin dosed on an eGFR from fourteen months ago**  
চোদ্দ মাস আগের eGFR দেখে মেটফরমিনের মাত্রা

**Why it must fire.** The plan's own sentence: an eGFR from two years ago is not current renal function. Before CP79 this prescription produced exactly the same screen as one checked against a result from this morning — MET-RENAL-45 fired, said 'do not start below 45', and nothing anywhere said the 41 it fired on was fourteen months old. A diabetic kidney at 41 can be at 28 fourteen months later, which is a different drug decision. The banded rule must still run, because a stale number is the best information there is, and the physician must be told what he is looking at. Both halves are the assertion: MET-RENAL-45 fires AND RENAL-EGFR-STALE fires beside it.

**কেন।** পরিকল্পনার নিজের কথা: দুই বছর আগের eGFR বর্তমান কিডনি-কার্যকারিতা নয়। CP79-র আগে এই ব্যবস্থাপত্রটি আজ সকালের ফলাফলের মতোই দেখাত — MET-RENAL-45 কাজ করত, কিন্তু কোথাও বলা থাকত না যে 41 সংখ্যাটি চোদ্দ মাসের পুরনো। ডায়াবেটিক কিডনি চোদ্দ মাসে 41 থেকে 28-এ নামতে পারে, আর সেটি ভিন্ন সিদ্ধান্ত। নিয়মটিও চলবে, সতর্কবার্তাটিও আসবে — দুটোই এই দৃশ্যের দাবি।

**Citation.** DTHCMS implementation plan CP79, recency rules; KDIGO 2024 CKD Evaluation and Management s1.4, monitoring frequency by GFR category. Window: core.facility_renal_policy, six months, PROPOSED AND UNAPPROVED.

**The patient.** 61 years old; not pregnant; eGFR 41; diagnoses E11.9, N18.3; asked about allergies, none known; on nothing already.

**Prescribed.** Comet 500 mg — Metformin hydrochloride (1000 mg a day).

**The engine must say.** verdict `WARNINGS`; `MET-RENAL-45` FIRES (WARN) on line "1"; `RENAL-EGFR-STALE` FIRES (WARN) on line ""; `MET-RENAL-30` must NOT fire.

## 35. NO-CREATININE-ON-A-RENALLY-DOSED-DRUG

**Metformin for a patient with no creatinine ever recorded**  
কখনও ক্রিয়েটিনিন হয়নি এমন রোগীকে মেটফরমিন

**Why it must fire.** The plan's manual verification, third case: prescribe metformin with no creatinine on file and the system must state that safety cannot be verified. It is the commonest real presentation in this clinic — a new patient, a new diagnosis of type 2 diabetes, and metformin written before any bloods come back — and it is the case where silence is most tempting and most dangerous, because nothing looks wrong. Two findings are required and they are different: MET-RENAL-30 cannot verify itself because its predicate has no number, and RENAL-EGFR-ABSENT says the drug needs one at all. The second is what makes the failure visible when no renal rule happens to be approved.

**কেন।** পরিকল্পনার নিজস্ব যাচাইয়ের তৃতীয় ক্ষেত্র: নথিতে ক্রিয়েটিনিন নেই এমন রোগীকে মেটফরমিন দিলে সিস্টেমকে বলতেই হবে যে নিরাপত্তা যাচাই করা যায়নি। এই ক্লিনিকে এটিই সবচেয়ে সাধারণ বাস্তব চিত্র — নতুন রোগী, নতুন টাইপ-২ ডায়াবেটিস, রক্তপরীক্ষার আগেই মেটফরমিন। এখানেই নীরবতা সবচেয়ে সহজ এবং সবচেয়ে বিপজ্জনক, কারণ বাইরে থেকে কিছুই ভুল দেখায় না।

**Citation.** DTHCMS implementation plan CP79 acceptance criterion 3 and its manual verification; US FDA metformin labelling, 2016 revision (obtain eGFR before initiating).

**The patient.** 47 years old; not pregnant; **no eGFR on file**; diagnoses E11.9; asked about allergies, none known; on nothing already.

**Prescribed.** Comet 500 mg — Metformin hydrochloride (1000 mg a day).

**The engine must say.** verdict `CANNOT_VERIFY`; `MET-RENAL-30` CANNOT_VERIFY (BLOCK) on line "1"; `RENAL-EGFR-ABSENT` CANNOT_VERIFY (BLOCK) on line "1".

## What this suite cannot test yet

Scenarios that matter and cannot be written against the model as it stands. Each names what it would need.

### Metformin and iodinated contrast

Named in the brief and real: contrast-associated acute kidney injury on metformin is the classic hospital referral. It cannot be written as a rule today because a planned radiology procedure is not in this system's model at all — there is no order, no appointment and no code for it, so there is nothing for a rule to test. It needs an orders model before it needs a rule.

_Needs:_ A procedure or radiology-order model (not in any checkpoint before CP80).

### Carbimazole specifically in the first trimester

The clinically correct rule is carbimazole before 16 weeks and propylthiouracil after. Gestational age is not in the model, so CBZ-PREG warns for the whole of pregnancy and asks the physician to check the trimester. Already recorded as a known gap in docs/medication-rules.md §10.

_Needs:_ Gestational age on the patient record.

### Any pregnancy rule, for a patient not coded O24.4

Pregnancy status is not a field anywhere in DTHCMS. The only thing in the record that entails it is the ICD-10 code O24.4, diabetes arising in pregnancy. Every other pregnant patient reaches the engine as UNKNOWN, so all seven pregnancy rules answer 'cannot verify' — correctly, and uselessly. This is the largest single gap CP78 found.

_Needs:_ A pregnancy status field, captured at registration or at the vitals station.

### Any hepatic rule, for any patient

Liver function is not graded anywhere in this system — no observation code, no assessment. All three hepatic rules therefore answer 'cannot verify' for every patient, always. A default of NONE would be a fabricated clinical assessment and would disarm two BLOCK rules, so the engine says it cannot verify instead.

_Needs:_ A hepatic impairment grade, or an ALT/bilirubin-driven derivation like CP43's eGFR.

### Carbimazole beside methimazole

Carbimazole is a prodrug of methimazole, so prescribing both is the same drug twice. Migration 00058 records them as two separate molecules, because recording carbimazole AS methimazole would be wrong for every other purpose. A class-level duplicate rule on ANTITHYROID would catch it; none is seeded, and whether to write one is a clinical decision.

_Needs:_ A DUP-ANTITHYROID rule, if Dr. Nahid wants one.

### Class-level duplicate therapy where one of the two is a combination tablet

A fixed-dose combination carries its own class code — Pioglitazone + Glimepiride is THIAZOLIDINEDIONE_SULPHONYLUREA_FDC, not SULPHONYLUREA — so a class-level duplicate rule does not see it. The molecule-level rule catches it through the components model, so no patient is missed, but a rule Dr. Nahid writes expecting class-level coverage will silently under-fire on every combination. Asserted, not fixed: the fix is either a class hierarchy on the formulary or the rule naming all the FDC classes the way CP77's seeded rules already do, and which one is right is a modelling decision rather than a bug.

_Needs:_ Either a class hierarchy in core.medication_class, or the rule naming each FDC class explicitly.
